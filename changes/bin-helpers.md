- A harness binary in a shared bin folder, such as `/usr/local/bin` or `~/.local/bin`, got only its own file in the sandbox. Codex 0.167 starts `codex-code-mode-host` from the folder of its binary, so every shell command failed with "codex-code-mode-host is missing". paddock now also mounts the helper programs of a harness, read-only. In a home bin folder these are the executable files named `<harness>-*`. In `/usr/bin` and the other system folders they are only the names that the profile lists in `[locate] helpers`, so `claude` does not get `claude-desktop`. If a helper is a symlink, paddock mounts the file that it leads to, and its install folder only for a known tool install such as mise, never the home or a folder above it. MCP servers get no helpers.
