- New: (experimental) the horse store reads and writes Codex 0.166.0 rollout files. The hidden commands are `paddock horse ingest-codex` and `paddock horse project-codex`.
- New: (experimental) in horse mode, a Codex child of `paddock-host spawn` runs as `codex app-server`. An approval request gets the answer that the plain Codex run of the profile gives, never a wider one. Each answer is one line in `approvals/<session>.jsonl` of the horse store.
- New: (experimental) an interactive Codex in horse mode gets queued entries through the pty relay. paddock sets the `notify` program in the sandbox copy of `config.toml`, and your own `notify` still runs after it. If the screen looks idle but `notify` never came, paddock writes one `pty.no_stop` ledger line and one warning. A command that sets `-c notify=...` keeps the entries queued.
- New: (experimental) `paddock horse swap SESSION BRANCH` continues a Codex session at another branch under the same thread id, so the cached prefix up to the fork point stays warm. If a headless run holds the session, the swap waits for the end of the turn, or stops it with `--interrupt`. An interactive run refuses the swap until it ends. With no run, `--codex-home` names the rollout. A swap that loses cached tokens needs `--yes`, and the old head stays in the store.
- New: (experimental) `paddock horse fork SESSION --warm` opens a warm side branch of a held Codex session under the cache key of the parent. The parent waits until `paddock horse fork SIDE --close` or the end of the run. `paddock horse log` marks its nodes `live`, and no codec writes such a session back.
- Fix: when two terminal relays run in one process, a size change of the terminal reaches each of them.
