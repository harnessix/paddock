- Fixed: on macOS, `paddock codex` (`--backend auto`) in a git project picked the VM backend, which then could not find the agent ("the run needs borrow (Linux only)"). Seatbelt gives the borrow folder, so a terminal agent now always gets Seatbelt. `auto` picks the VM only when the user asks for it (`[macos] backend = "vm"` in the user configuration). A run that needs what Seatbelt cannot give (window mode, an overlay, the private keyring) stops before the start with one line that names it and the command that works, and is no longer moved into the VM. `[macos] needs_pty` no longer moves a run into the VM either.
- Fixed: the VM guest refuses a run whose agent program it does not have, before the run starts: "codex is not installed in the VM (...). Start it with Seatbelt: paddock run codex --backend seatbelt".
- Fixed: in a Seatbelt run, `python3` and `git` printed "xcrun: error: couldn't create cache file". Apple's `/usr/bin` shims write their cache in the user temp folder of the host, which the sandbox cannot write, and must not: the host's xcrun trusts that cache. The run now has the developer tools of `xcode-select -p` before `/usr/bin` on PATH, and `DEVELOPER_DIR`, so a command found by PATH skips the shim. A login shell (`zsh -lc`, as codex runs commands) runs `path_helper`, which puts `/usr/bin` first again: for it, the run sets `xcrun_db` to a file in its private temporary folder, so xcrun keeps its cache there. `path_helper` changes only PATH, so the variable stays. The host temp folder stays closed.
- Fixed: on macOS, a run no longer says "memory.high is not applied: this run has no accessible systemd scope", and `paddock explain` shows the memory line only where paddock can apply the limit (Linux).
- New: `paddock doctor --escape --backend seatbelt` (and `--backend auto` on macOS) runs the escape probe in a real Seatbelt sandbox. It checks that the real home, `~/.ssh` and the other secrets, `~/Documents`, `/Users` and the other users, the host `/tmp` and paddock's state, configuration and sandbox homes are out of reach, that TMPDIR is private, that the project is writable and its `.env` masked, that the network matches the mode (`--network`, `--online`), and that `python3` and `git` run without the xcrun cache error, also in a login shell (`xcrun-login-shell` is a real check, no longer a skip).
- Fixed: `paddock doctor --escape` on macOS reported `FAIL real-home-unreadable` and `FAIL real-home-unwritable` for the sandbox's own home. The Seatbelt run moved every variable with a path in the host home into the sandbox home, the probe's host paths too. The probe variables (`PADDOCK_PROBE_*`) now reach the run as the host paths that paddock knows. A Seatbelt run also starts in its private temporary folder, so the shell no longer prints "shell-init: error retrieving current directory" when paddock starts from a folder that the sandbox cannot read.
