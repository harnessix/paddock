- New: `paddock app share NAME add|remove|mode|list`, `paddock app network NAME ask|allowlist|none` and `paddock app clipboard NAME --to-app on|off --from-app on|off` change the grants of an app of the macOS guest while it runs, with no restart. paddock gives the running VM a new share set, and the firewall reads the new mode for each connection. A switch to `none` closes the open connections. Each change is kept in `grants.json` of the profile for the next start. paddock writes the file atomically under a lock, and only after the session took the change.
- New: a new folder is read only by default. paddock refuses the home folder, system folders, `~/Library`, `~/.ssh`, the keyring folders and the folders of paddock's own data, with one line that names the reason. `share list --json` shows the open files per folder, as the guest agent counts them, and the last use. `share remove` refuses a folder with open files unless you give `--force`.
- New: `paddock app status NAME --json` has `open_handles_per_share`, `clipboard`, `devices` (each with `applies: next-start`) and `changes`, the last 20 grant changes with their source and time. Each change is also a `grant` line in the event log of the profile.
- Changed: on the firewall panel, Return now answers `Allow once`, and `Always allow` takes a click or Command-A. A reflex Return no longer makes a permanent rule.
