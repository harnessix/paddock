- Fixed: `paddock exclave run -- cargo test` failed with "cargo: not found" on a peer whose user has Rust through rustup. The peer now gives every run the user's `~/.rustup` and `~/.cargo/bin` read-only, with `RUSTUP_HOME` set and the rustup proxies first on PATH. A sandbox gets the same binds, but only for a Rust project. The peer refuses a run when one of the two folders resolves to the home, a folder above it, `~/bin`, `~/.local/bin` or a folder that holds Cargo credentials. The peer owner turns the toolchain off with `[exclave.serve] rustup = false`.
