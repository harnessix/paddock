- New: (experimental) a sandbox in horse mode sees its own horse at `/dev/paddock/horse/self/`: the DNA, the lineage, and a folder for each session with its head, status, inbox and log. `paddock-host horse` reads the same data through the broker, also on macOS. If the sandbox has no `/dev/paddock/horse`, for example when FUSE is missing, the run says why.
- New: (experimental) a sandbox can change the context of its own horse with one command per write to `self/ctl`, or with `paddock-host horse ctl`: `fork`, `append`, `move`, `view` and `disconnect`. The answer of the last command is the content of `self/ctl`. `view SESSION NAME FILTER` makes the read-only file `self/views/NAME`, and `disconnect` ends the custody of a session at its next safe point.
- New: (experimental) `ctl` needs a grant: `paddock horse grant SANDBOX --allow fork,append` with a budget of commands (`--commands`) and of lost cache tokens (`--tokens`, default 0). `paddock horse grants` shows what each grant used, and `--revoke` removes it. A write without a grant, out of budget or on another horse fails with EACCES.
- New: (experimental) the prefix guard judges each `ctl` command first. An append at the end passes at once. A command that breaks the cached prefix shows an approval card with the lost tokens and the cost. A denied command fails with EPERM and changes nothing. Each command writes one line to the device ledger.
