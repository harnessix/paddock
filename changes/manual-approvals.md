- New: manual mode is a first-class choice. `[run] approvals = "auto" | "manual"` in the user configuration, `[run.agents.NAME] approvals` for one agent, and `[run] approvals` in a project's `paddock.toml` choose who approves the agent's steps. The order is the command line, the project, the agent, the user configuration, then the default `auto`. `paddock run --manual` (the old `--no-yolo` stays as an alias) and `paddock run --auto` choose for one run. The sandbox is the same in both modes.
- Changed: in manual mode paddock no longer answers the agent's trust question for the project (Claude Code's `hasTrustDialogAccepted`, Codex's `trust_level`, and the folder trust screens of Codex and agy). The agent asks it, as it does outside paddock. Before, `--no-yolo` still answered it.
- Security: `[run] approvals = "auto"` in a project `paddock.toml` needs the one-time approval, because an agent in the sandbox can edit the file. `"manual"` needs none. A project file cannot set `[run.agents]`.
- New: the mode shows where a run shows: the start line ("codex in PROJECT (backend seatbelt, network egress, display off, manual approvals)"), `paddock explain` (`approvals` and `approvals_origin` in `--json`), `paddock ps --json` and `paddock board --json` (`approvals`: `auto`, `manual`, or `command` for `paddock wrap` and desktop apps), `paddock shims list`, and the run cards of `paddock tui` (a "manual" tag). In the TUI's new run dialog, `Ctrl+A` switches the mode of the new run.
