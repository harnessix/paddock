- New: In horse mode, a Codex child that is spawned with a task runs as `codex app-server` under live custody. The task is the first user entry of its session, and the run ends when the thread is idle and the inbox is empty. Interactive Codex runs still get the final ingest only.
- New: `paddock horse swap SESSION BRANCH` continues a Codex session at another branch under the same thread id, so the cached prefix up to the fork point stays warm. If a run holds the session, the swap waits for the end of the running turn (or interrupts it with `--interrupt`), and Codex loads the thread again from the swapped rollout. If no run holds it, the rollout under `--codex-home` is swapped. The old head stays in the store as its own session, and each swap is a `swap.live` or `swap` event.
- New: The prefix guard judges a Codex swap by the tokens after the fork point, and a Codex fork under a new thread id as cold. A swap that loses cached tokens needs `--yes`.
