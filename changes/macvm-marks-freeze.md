- New: the windows of a session of the macOS guest carry the paddock marks. The frame is sage in every network mode, also `ask`, because every connection of the guest goes through paddock's proxy. The badge gains `vm` and the name of the guest input source while it differs from the host's, for example `paddock · chatgpt-desktop · ask · vm · 2h`. The menu entry names the app, `ChatGPT (paddock)`. `paddock windows --json` shows the `tone` and the `badge` of each window.
- New: a session of the macOS guest is listed with the running sandboxes as `macvm-<app>`. `paddock freeze macvm-<app>` pauses its VM through the `pause` line of the control socket, and `paddock thaw` sends `resume`. A second freeze does nothing. The audit log and the kv state `sandbox:<id>` are as for every freeze. `paddock app stop` of a frozen session thaws it first, and a quit from the Dock or Cmd-Q resumes the VM before it quits, so the state is saved.
- New: when a screen goes away during a session of the macOS guest, the windows on it come to the main screen, and the badge says `display changed, restart for full size`.
- New: `paddock app run` on macOS refuses a host before macOS 14, a Mac without Apple silicon and a third session of the same user with one line each, before any clone.
- New: the README has the section "App mode on macOS in a guest VM": the first run, the commands, the marks and freeze, the failure behavior, the reset tiers and backups, the status and logs, the keyboard and input method rule, Spaces, VoiceOver, the clipboard, the limits, the performance targets and baseline, the security table, and the Mac checks that paddock has not confirmed yet. The Seatbelt app mode is now "App mode on macOS under Seatbelt".
