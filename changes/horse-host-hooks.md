- New: (experimental) `paddock horse adopt` adds paddock's hook entries to the host configuration of Claude Code, Codex, Grok Build and agy, so each turn of a host session reaches the store when it ends. A new Claude Code or Codex session gets the DNA of its horse. A Claude Code host session gets its queued messages when its turn ends, or with your next prompt. paddock copies the file before the first change, marks each entry with `--mark paddock-horse`, adds its entries after yours, and refuses a symlink or a file that is not a JSON object. It inserts its entries as text in your layout, and every other byte of the file stays. `--off` cuts out exactly paddock's entries, so the file is the original again when you did not change it. A hook waits at most a few seconds for another sweep, reads only the session of its event, and gives a queued message to the harness before the message leaves the queue. A second `paddock horse adopt` puts the entries in again when an upgrade moved the paddock program. `--no-hooks` changes no configuration. A sandbox copy of the hook file does not get these entries.
