- Fixed: a grants file with an unknown network mode starts the app with network `none`, no saved folders and the clipboard off, and warns. Before, it started in `ask`, where a saved allow rule let traffic through.
- Fixed: a grants file that is missing from a profile that saved grants before also starts closed and warns. The damaged-file warning now says to set the network again after you move the file away.
- Fixed: a network or folder change while the app starts can no longer be saved only for the next start: the start reads the grants again under their lock and holds it until the session is registered.
- Fixed: when only the final sync after the grants file rename fails, paddock keeps the live change, which matches the saved file, instead of reverting it.
- Fixed: while such a grants file is missing, a folder or clipboard change is refused until you set the network again. Before, that save wrote a new file without a network mode, and the next start used `ask`. A rule change of `paddock app rules` still applies, because the rules are in their own file. Only its note in the grant history is dropped, with a warning in the log.
- Fixed: a folder or clipboard change that the save refuses no longer reaches a running app. Before, paddock applied the change live and then tried to undo it. When the undo failed, the app kept a folder that no saved grants held.
- Changed: when a save fails after a live change and the undo fails too, the error now says that the app keeps the change until it stops and that the next start does not have it.
- Fixed: a start waits for the grants lock only while another command holds it. Other errors, such as a profile folder that cannot be made, now stop the start at once with their own message. Before, they waited 30 seconds and said that another command held the lock.
