- Fix: on macOS, an approved command of the gateway executor starts in its working folder. Before, its shell started in the folder of the executor, which the Seatbelt profile does not let it read, and printed `getcwd: cannot access parent directories: Operation not permitted`. `PWD` names the folder as given, so `pwd` prints `/tmp/x` and not `/private/tmp/x`.
- Fix: on macOS, a `forge` call can run a `gh` outside the system folders and the home. The folder of the program that the broker found is read-only in the Seatbelt view.
- Fix: the program of an exec or serve device gets `PWD` set to its working folder, so `pwd` prints the folder as named in `cwd`, also when the path has a link in it.
- Fix: the short socket folders of macOS keep 24 bytes for the socket name, so `credentials.sock` and every other socket of a run fits in 103 bytes for any id. An id that is too long becomes a SHA-256 hash, which stays the same across builds. The thread launcher of a device instance uses these folders when the instance folder is too deep.
- Fix: on macOS, paddock raises its soft limit of open files from 256 to the hard limit, at most 10240. The device socket server uses one file per connection, not two, and waits 20 ms after a failed accept instead of spinning.
- Fix: a workspace folder of a macOS guest session is checked by its real path too, and the real path is shared. A symlink in the home that points into `/etc` or `/tmp` is refused. A folder in the home is never a system folder, even when the home is under `/private`.
- Changed: `paddock windows --json` on macOS prints `{"api_version": "paddock.windows/v1", "windows": [...]}`, the envelope of Linux, and no longer a bare list.
