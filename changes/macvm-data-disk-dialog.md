- Fix: a new macOS guest profile no longer shows the dialog "The disk you attached was not readable by this computer" at its first boot. paddock formats the new data disk on the Mac as a plain user (GPT, APFS, the volume `Data`) before the first boot, and the guest agent moves the home onto the empty volume. If the format fails, the disk stays blank and the agent formats it in the guest as before.
- Fix: if a disk dialog shows in the guest anyway, the guest agent presses Ignore (never Eject), and the session logs a `dialog` line. A dialog that the agent cannot dismiss shows on the desktop as a window of the app `system`, and the session prints a line that names it.
- Fix: `paddock app stop` of a macOS guest session whose app does not run in the guest goes on at once to the save. Before, it waited 70 s and stopped the VM without a save, so the next start was cold.
- Fix: when the guest cannot select the host's input source (for example Pinyin), it uses the ABC layout (or US) with one info line, instead of the error `cannot select the input source`.
- The guest agent mounts the data volume by its device and its UUID, not by the name `Data`, which the system volume of the guest can also carry. A copy of the home that broke off is never taken for the home.
