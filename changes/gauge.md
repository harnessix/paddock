- New: `paddock gauge [FEATURE]` shows how far a Spec Kit feature is, from the history of `tasks.md` and not from what the agents say: the done tasks with and without evidence, the tasks discovered per day, the reopened tasks, the fails after done, the age of each open task, and the time that tasks sat almost done. It forecasts the P50 and P85 of the finish date and of the final task count with a seeded Monte Carlo, says "not converging" when new tasks arrive as fast as tasks finish, shows the trend of P85 and a burn-up chart with the scope line. `--json`, `--strict`, `--seed`, `--window` and `--at` change the output.
- New: a task counts as done with evidence only when its work is merged, its review passed or a gate passed for it. `paddock spec gate TASK GATE pass|fail|skip` records a gate result on the host. A gate that only skipped, or a worker report that says its tests skipped and names no passing run, does not count as done.
- New: `paddock spec appetite FEATURE VALUE` sets the time budget of a feature (for example `3d`). paddock sends an `appetite` event to the mailbox of the run at 50 %, 80 % and 100 % and at every 25 % after that, each one once. It never stops the work.
- New: inside the sandbox, `paddock-host gauge` gives a coordinator the same gauge, computed on the host.
- New: paddock keeps a log of the task states next to the task records, so a project without git gets a task history from its first run on.
