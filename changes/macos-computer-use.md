- New: computer use of the macOS guest. `paddock mac status|screenshot|click|move|drag|scroll|type|key|ax|press` sees and operates one app session (`--app NAME`), or the whole guest display (`--desktop`), and prints JSON. Coordinates are pixels of the last screenshot of the same target. A screenshot of an app shows only its windows, and input outside them is refused. The guest agent captures with ScreenCaptureKit and posts input with CGEvent into the guest session, never on the host.
- New: `paddock mcp mac` serves the same tools as an MCP server on stdio, with screenshots as images. In a sandbox, `paddock-host mac` and `paddock-host mcp mac` reach the guest through the new `mac` capability (ask by default). A session grant covers one target. The skill `paddock-mac` teaches the loop of observe, act and verify, and `paddock skill install` installs it.
- New: the frame stream of the guest agent (`frames.subscribe` and `frames.stop` on the `guest-computer` port) sends a PNG only when the picture changes, at most `max_fps` per second.
- Change: `paddock macvm setup` allows Screen Recording for the guest agent. A golden image from an older paddock has no such permission, so screenshots fail with `screen_recording` until you run `paddock macvm setup` again.
- Security: in a sandbox, paddock chooses the session of a `mac` request before it asks, and the card and the session grant name that session and its pid. The card shows every typed character (a Return as ⏎), a request types at most 1000 characters, and the card says what a grant reaches, also the host clipboard in the guest. In app scope the guest agent refuses the known shortcuts of the system by any name of their key (not a shortcut that the user changed or added), refuses the Help menu shortcut by the character of its key on the guest's layout, clicks on the menu bar, drags and double or triple clicks with the right button or ctrl, and every input and every press but escape while a menu is open. It stops keys and text when the app leaves the front or a menu opens. If a drag opens a menu, the guest sends escape before the let-go. It looks for the menu for 0.5 s after the press and again before the let-go. The guest reads the keyboard layout on the main thread. A failed post releases the keys and the mouse button that it held down. A guest that never answers or streams frames cannot hold a host call past its time or fill its memory, and text from the guest loses its control characters before it reaches a terminal.
