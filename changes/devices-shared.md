- New: `scope = "shared"` in a `[devices.NAME]` table runs one instance of the device per user. Every sandbox that has the grant uses that one instance. Use it for a program that is expensive to start, or that holds a warm state. The first broker that needs the device starts `paddock deviced NAME`. Every broker then connects to one socket in the runtime folder. The instance ends after its last run ended and `idle` seconds passed without a request.
- New: each run holds one open connection to the instance as its lease. A run that `kill -9` removes drops its lease at once. One broker that fails never takes the instance down.
- New: `paddock device install NAME` hands the socket of a shared device to the user manager. On Linux it writes two systemd user units. On macOS it writes a LaunchAgent with a `Sockets` entry. The first connection then starts the instance, and no broker starts it itself. `paddock device uninstall NAME` removes those files again.
- New: without an install, `systemd-run --user` starts the instance where a user manager runs. Without a user manager, the first run owns the instance. paddock then logs a notice that names that run.
- New: `paddock device stop NAME` ends the one shared instance of the user. `paddock device restart NAME` ends it so that the next one reads the table as it is now. With a user manager it also starts the new one at once. `paddock device logs NAME` prints its log.
- New: `paddock device ls` shows `shared, 3 users`. `paddock ps` shows the instance once, at the top, with its user count and its unit. `paddock device check NAME --hold SECONDS` keeps a device warm while you look at it.
- Security: a shared instance serves the device table that it read at its start. It refuses a run whose view of that table differs. The request fails with `EIO`. The catalog says the device was reconfigured and names `paddock device restart NAME`. So an edit of the user configuration is never served half old and half new.
- Changed: `scope = "shared"` with `run = "host"` is now a parse error that names the fix. A host program shows its approval card per sandbox. `caller = ["project:ro"]` was already refused for a shared device.
- Changed: the smallest `idle` of a device table is one second instead of ten.
- Fixed: a shared instance that a run owned ended right after the first request of that run. The run starts the instance from the thread of that request, and the instance asked the kernel to end it when that thread ended. The instance now watches the run process itself, so it lasts as long as the run.
- Fixed: `paddock device install NAME` and `paddock gateway install` now work when `XDG_CONFIG_HOME` of your shell is not the folder of the user manager. paddock links the units into the user manager in that case. The service unit now gets your `XDG_*` folders, so the instance reads the same configuration as paddock.
- Fixed: the state file of a shared instance in a systemd unit names that unit also when the unit has no session bus address.
- Changed: if `systemd-run --user` refuses the unit of a shared instance, the run starts the instance itself and logs why. Before, the request failed.
- Fixed: a shared instance with no user left exited at once when the last lease dropped, not `idle` seconds later. It now counts `idle` from the moment the last user left, to the millisecond.
- Fixed: the state file of a shared instance was written twice at its start, once without the unit and the owner. `paddock ps` or `paddock device stop` could meet the new pid without them for a moment. The start now writes the whole record once.
