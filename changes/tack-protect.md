- New: tack has two levels of protection for each allowlist entry. At `protect = "uid"`, tackd on Linux runs the program as a helper account of your user (`_tack_<user>`, which `sudo paddock tack setup` makes), so your other processes cannot read its environment or memory. The program reaches your working folder through a POSIX ACL that tackd adds as you (read, and write with `write = true`), and files that it writes there stay yours. At `protect = "refs"`, the program runs as you, and other processes of your user can still read its environment: the audit, `paddock tack status`, `paddock explain` and the README say so.
- New: `gh` and the git credential helpers (`git-credential-*`) get `protect = "uid"` by default. Every other program gets `protect = "refs"`. Run `sudo paddock tack setup` again after this update, so that your helper account exists. Set `write = true` for `gh` if you use commands that write files, such as `gh pr checkout`.
- New: the programs that a program at `protect = "uid"` starts get references, not values. An exec wrapper first on its PATH puts the references back, and sends an allowlisted program to tackd. A program that starts another by its absolute path is not covered.
- New: each `started` line of the audit log says the level and the uid that the program runs as (the fields `protect` and `run_uid`). `paddock tack status` and `paddock doctor` show the level of each allowlist entry, and whether the helper account and POSIX ACLs work. `paddock tack check` shows the level of a start.
- New: `sudo paddock tack remove` also removes every ACL that tackd added, the helper accounts and `/var/lib/paddock-tackd`.
