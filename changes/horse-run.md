- New: (experimental) horse mode. `paddock run HARNESS --horse`, or `[horse] enabled = true` in the user configuration, keeps the sessions of the run in the horse store on the host. It works for dsh 0.2.1-rc.5, Claude Code 2.1.317, Codex 0.166.0, Grok Build 1.0.70 and agy 1.4.12. Another harness or version fails before the run starts. Runs without horse mode do not change.
- New: (experimental) in horse mode, paddock holds the session of the run (custody). It reads the session into the store after every turn, and it delivers queued entries only at a safe point, when no turn runs. A run that paddock cannot hold reads its session files into the store at the end.
- New: (experimental) `paddock horse append SESSION --text TEXT` queues an entry for the next safe point, as the newest entry. `--role` sets `user`, `system`, `developer` or `note`. With `--interrupt`, an interactive run stops the running turn with the interrupt key of the harness, and the entry goes out before older entries.
- New: (experimental) a child of `paddock-host spawn` with a task runs in the machine mode of its harness. paddock gives the task as the first entry after the DNA entry. The child ends when it is idle and its inbox is empty. The output of the custody is the output of the child. An empty task fails before paddock writes to the store.
- New: (experimental) an interactive run keeps its TUI. paddock relays the terminal through its own pty. If the hooks of the harness say that the turn ended and the screen is idle, paddock types the next queued entry into the TUI. The screen patterns are in the `[horse.pty]` table of each profile, and `paddock doctor` lists them as unverified. A run with no terminal, or a command that sets what paddock sets itself, keeps the entries queued and says so in one line.
- New: (experimental) the prefix guard warns if an operation loses the cached prompt prefix. Such an operation is a fork, an entry that is not at the end, a change of model, effort, tools, system prompt or cwd, or a long pause. It shows the size of the lost part and the cost, and the append form where there is one. `paddock horse guard SESSION` asks it.
- New: (experimental) `paddock horse status` shows the live sessions, their heads, inboxes, deliveries and the last guard verdict. The `run.end` event of each run names its custody, has its counts, and has `error` if the custody failed.
- New: (experimental) paddock reads a Claude Code, Codex or Grok Build session file also after a crash cut a line and the harness wrote on. It skips the cut line, as the harness does.
- New: (experimental) a detached run (`paddock run --detach`) refuses horse mode.
