- New: on macOS, `paddock app run NAME` runs the app in paddock's own macOS guest. It needs a sealed golden image. Without one it stops and names `paddock macvm setup`. `--backend seatbelt` keeps the older Seatbelt route.
- New: the start lines name the backend and its reason, the memory, the display and the shares. They also name the downloads folder and the network mode. The start line says cold or warm, with its seconds and its reason. The copy line says the app and its seconds.
- New: the guest gets a copy of the app bundle once per version. paddock clones the host bundle into the profile with an APFS clone. The guest copies it with `ditto` as `<Name>.app.partial` and renames it. So a killed session leaves no half app that can start. The old copy stays until the new one is whole. If a copy fails, paddock prints one line and the app runs from the old copy. The guest needs the size of the bundle plus 500 MiB free on its data disk.
- New: a session carries the app's own name and icon. They show in the Dock, in Cmd-Tab and in Mission Control. They come from `macvm/shims/NAME.app`, which holds a copy of `paddock-vm` and an ad hoc signature. If the paddock version in that bundle differs, paddock builds the bundle again.
- New: on macOS, `paddock app install NAME` makes `~/Applications/<Name> (paddock).app`. `paddock app install --drop` makes `~/Applications/Paddock Apps.app`, the drag target. An app bundle dropped on it becomes an app profile with its own launcher, and starts. The profile is `[apps.<slug>] bundle = "PATH"`. `paddock app uninstall NAME` and `paddock app uninstall --drop` remove them.
- New: `[apps.NAME] vm_memory = "6G"` sets the memory of the macOS guest for one app. The limit is half the memory of the Mac. `[apps.NAME] bundle = "PATH"` names the app bundle of a profile that the drag target added.
- Security: `paddock app run` refuses an App Store app in the macOS guest with one line. The guest has no Apple ID. The line says to install the vendor's download instead.
- Security: if the host bundle carried the user's approval, the guest removes the quarantine attribute from the copy. Otherwise the attribute stays.
