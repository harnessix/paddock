- New: the macOS guest of app mode gets its network exit. The guest has one network device, a stub on the host end of a socket pair in the session helper: it answers ARP for the gateway, one DHCP lease and its renew, DNS with `REFUSED` and ICMP echo to the gateway, and drops every other frame with one `network` line per minute per target in `logs/boundary.jsonl` of the profile, rule `no route: the guest reaches the network only through paddock's proxy`. The guest agent runs a CONNECT proxy on `127.0.0.1:3128`, the system proxy of the guest and the proxy of the app's environment (`HTTPS_PROXY`, `HTTP_PROXY`, `ALL_PROXY`). Each tunnel goes over vsock to the host proxy inside the session helper with a header line that names the guest process (pid, bundle, team, path, the outermost app of a helper), found from `net.inet.tcp.pcblist_n` and the Security framework. The host proxy reads that line when the first byte is `{`, refuses another token, closes a first line longer than 256 KiB, and passes the identity to the boundary log. The guest proxy caps open tunnels at 512 (`503` above), answers `502` within a second when the host does not answer, and the host closes idle tunnels at wake. The configure steps of the golden name the network service by its run time name (`com.redhat.spice.0` on macOS 15, not `Ethernet`). `packaging/macos/checks/macvm-network.sh` checks it on a Mac.
