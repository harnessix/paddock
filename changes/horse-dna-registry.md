- New: (experimental) published DNA. A reference `registry://org/name@version`, `@latest` or `@sha256:HASH` resolves through a list of index folders to a signed manifest and its DNA. A local trust policy lists which Ed25519 keys can sign for which org, and it refuses an unsigned or untrusted manifest by default. A published version cannot change.
- New: (experimental) `paddock horse registry` manages published DNA on the host. It has `key new`, `key show`, `trust add`, `trust list`, `index add`, `list`, `resolve`, `publish` and `sync`. `resolve` prints the manifest, the verdict and the hash, with no import. `publish` signs with the key of the host, or not with `--unsigned`. `sync` runs `git pull --ff-only` for an index that is a git checkout. `paddock horse dna use HORSE REF` grafts published DNA into a horse, and `explain` names the reference as the origin of its traits.
- New: (experimental) in a sandbox in horse mode, `paddock-host horse registry fetch REF [--use]` and `paddock-host horse registry sync INDEX` ask you first. The host does the work, and the device ledger gets one line. A denied fetch writes nothing. The answer holds no path, key, index name or trust entry.
