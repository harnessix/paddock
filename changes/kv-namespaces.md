- Security: paddock kv has named namespaces. `[kv.namespaces.NAME]` of the user configuration names the projects (`projects`) and optionally the harnesses (`harnesses`) that share the scope `ns:NAME`. Other sandboxes cannot read or write it. Use a namespace instead of the `user` scope when only a few projects share state, for example compile slots.
- New: `paddock-host kv ... --scope ns:NAME` for get, mget, put, mset, delete, list, history, watch, claim and release. A member sees no approval card, because the user configuration is the approval. A sandbox that is not a member gets exit code 3 and a message that names the namespace and the key to change. A namespace that does not exist gets exit code 4. A spawned sandbox is a member only if every sandbox above it is a member. Running sandboxes read the table again at each request.
- New: `paddock kv list|get|delete|release --ns NAME` on the host, and `paddock kv put|watch|claim --ns NAME`, which act as the user without `--as`. `paddock kv overview`, `paddock doctor` and `paddock-host kv info` show the namespaces.
- A project `paddock.toml` cannot define a namespace: `[kv]` is only read from the user configuration.
