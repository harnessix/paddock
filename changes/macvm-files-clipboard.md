- New: the macOS guest (`--backend macvm`) shares the workspace folders as `ws-1`, `ws-2` and so on under `/Volumes/My Shared Files` in the guest, with `--ro PATH` for a read-only one, and refuses `/`, the home folder and its parents, `/Users`, `/Volumes`, the system folders, `~/.ssh`, `~/Library` and the keyring folders with one line per folder. A `.env` or key file in a folder stops the start and names the file, unless `[apps.NAME] unprotected_workspaces = true`.
- New: a file, text or image dropped on a session window is copied into `drop/<time>-<n>/` of the profile (never the original), at most 2 GiB per drop, and opened in the guest app. The clipboard moves both ways only while a session window is key, with text, RTF, HTML, PNG, TIFF and file URLs, never a concealed or transient item of a password manager, up to 16 MiB. `paddock app files NAME` opens the downloads folder of the profile, where every download of the guest lands.
- Security: the `guest-files` port of the macOS guest takes 16 MiB per transfer, 64 transfers per minute, and closes a transfer idle for 10 s.
