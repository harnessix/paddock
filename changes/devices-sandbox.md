- New: the device sandbox on Linux. A device table with `run = "sandbox"` runs its program in a bubblewrap sandbox of its own, built from `[devices.NAME.sandbox]`: the system read-only, an empty home, its own `/tmp` (`tmp = "4G"`), no network, widened by `network`, `connect`, `ro`, `rw`, `home`, `env`, `env_pass`, `credentials` (an ssh agent per instance, secret FIFOs), `caller = ["project:ro"]`, `mem` and `cpus`. One instance per agent sandbox, started at the first request or `with-sandbox`, in a systemd scope `paddock-dev-<sandbox>-<name>`, ended with the run, with `paddock stop`, and when the paddock process dies.
- New: `connect = ["2222:mac.local:22"]` on the host side: the broker resolves and connects from the host, one connection at a time, with one audit line per connection (host, port, bytes, duration, `lan`), never content.
- New: `paddock device check NAME [--send REQUEST]`, `logs NAME [--sandbox ID] [-f]`, `stop|restart NAME [--sandbox ID | --all]` and `stats NAME [--since 7d]`. `paddock ps` shows `device NAME (sandbox, running 3m, pid N)` under a sandbox, `--json` lists them under `devices`. `paddock device ls` shows the running instances. `paddock freeze` freezes the device scopes of a sandbox with it.
- New: a state file per instance (`<state>/devices/instances/NAME/ID.json`, written whole) and a log per instance (`<state>/devices/log/NAME/ID.log`, 10 MiB, one rotation). Stale files of a killed process go at the next start.
- Changed: a supervisor that dies restarts at the next request after 1 and 2 seconds; the third death within a minute makes the device `failed` with `how_to_fix` naming `paddock device logs` and `paddock device restart`.
- Changed: `kind = "command"` tables run in one device sandbox per run instead of one `systemd-run` unit per request. The view, the envelope, the card and the audit are the same; a missing program still answers `is not on the PATH`. `shape = "serve"`, `start = "with-sandbox"` and a sandbox profile are available for `run = "sandbox"`.
- Changed: `paddock device-serve` takes `--env-pass NAME` for the variables of the profile that the program gets.
- Security: policy.rs keeps refusing a device mount of `/`, the home (unless `home` says so), a protected folder or another run's folders; a single read-only file of `ro` under a protected folder passes, because the user named it on the host. `deliver` credentials reach a device as a file only; `gateway` and `intercept` are refused with the fix.
- Removed: `devices/command.rs`, the per-request `execbox` runtime of command devices.
- Fixed: a device instance started by the first request of a `start = "first-request"` device ended with that request. bwrap runs with `--die-with-parent`, and the kernel sends that signal when the thread that started the process ends, not when the process does; the request ran on a thread of its own. A keeper thread starts bwrap now and lives until it ends, so `paddock ps` keeps the row and the next request finds the instance running.
- Fixed: `PADDOCK_CALLER_MOUNT` was never set in a device program: the broker and `paddock device check` did not name the mount of the caller's project in the request. With `caller = ["project:ro"]` the program gets `/run/paddock/caller/project` in the variable.
- Fixed: a request that a streaming device rejected (exit 65 of the program) made `paddock-host device` exit with 7 after it printed the status lines of the rejection. The lines of a rejection or a failure now stay out of the response, and the read fails at once with `EINVAL`, so the exit code is 8 as documented.
- Fixed: `paddock doctor --escape --device NAME` reported the runtime folder as visible when the folder is not under `/run/user`. The sandbox masks that folder with an empty read-only file system, so the path exists and shows nothing. The check now looks for entries of the host in it.
