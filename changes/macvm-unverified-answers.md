- Fixed: an allow answer on a firewall question of a macOS guest no longer leaves the question open until the app restarts. paddock cannot prove that the answer comes after the last sleep of the Mac, so it denies the connection once, changes no rule, and shows the next question. The session log and `paddock app status` say why, with the command for a rule. Deny answers and the pause notice apply again. A notice whose answer cannot be read for five seconds lets asking go on; a short failure no longer drops the answer. A question whose answer file is damaged is denied once after five seconds, so it no longer holds every later question back. A card that is missing or cannot be read closes the same way. While the approval store cannot be locked, the question stays open and is tried again. `paddock approvals answer` says when an allow will not apply.
- Fixed: an answer no longer fails with "approval evidence identity changed" when the card changes while the answer waits for the store lock.
