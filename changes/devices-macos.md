- New: the device sandbox on macOS. A device table with `run = "sandbox"` runs its program under Seatbelt (`sandbox-exec`) with a profile built from `[devices.NAME.sandbox]`: the system read-only, a private home and `TMPDIR`, `ro` and `rw` at their own paths, the real home denied unless `home` says else, no IP network, or the `connect` ports on localhost only. `caller = ["project:ro"]` gives the caller's project at its host path (`PADDOCK_CALLER_MOUNT`), a secret file is a FIFO in the instance folder, and the ssh agent of a credential is a socket the sandbox can only connect to. `paddock ps`, `paddock device check|logs|stop|restart|stats` and `paddock device ls` work as on Linux; the state file says `"backend": "seatbelt"`, and the catalog entry of a sandbox or host device says `"platform"` (`macos` or `linux`).
- Changed: on macOS, `mem` and `cpus` of a device table are accepted and ignored, and `paddock doctor` prints one line per table that sets them. `paddock freeze` does not reach a device instance on macOS.
- Changed: the sockets of a device instance on macOS live in two short folders under `/tmp/paddock-<uid>`, not in the instance folder: the instance folder path is longer than a Unix socket address allows there.
