- New: each run has a mailbox between the agent and its starter. `paddock mail watch RUN` prints one line for each message of the agent and each event of paddock, until the run ends. The events are `started`, `ended` (with the exit code), `gone` (the run's paddock process was killed behind a pane that still looks alive), `idle` (a detached run is quiet with unread mail), `card` (an approval card waits, with what it asks) and `child-started` and `child-ended`. `paddock mail send`, `ls` and `show` send and read messages. A watch keeps its place, so a restart shows each line once.
- New: inside the sandbox, `paddock-host mail wait|send|ask|status` and the files `/dev/paddock/mail/in` and `/dev/paddock/mail/out` read and write the mailbox of the run. A message holds at most 64 KiB of text. A longer text goes into a file in `.paddock/`, and the message names it with `--ref`.
- Changed: `paddock run --detach` prints a third line, `mail: paddock mail watch ID`. The first prompt of a detached run ends with a short note about the mailbox, and Claude Code gets the same note at the start of each session.
- Changed: `paddock gc --homes` also removes the mailboxes of runs that ended longer ago than `--older-than`.
- New: a message reaches a Claude Code agent that never reads its mailbox. At the end of the agent's turn, a Stop hook keeps the turn going with the unread messages. A message sent with `paddock mail send --interrupt` comes after the agent's next tool call. Each message comes once. If the host does not answer, the turn ends as usual.
- New: a `delivered` event in `paddock mail watch` names the messages that reached the agent, and how. `paddock mail ls RUN` shows for each message that you sent whether and how it reached the agent. `paddock mail send` says when the agent gets the message.
