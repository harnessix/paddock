- New: tackd starts the allowlisted programs with their secrets on Linux. `paddock tack setup` (without sudo, or with sudo for the user who runs it) puts a stand-in for each allowlisted program first on PATH, in login shells, environment.d and paddock sandboxes. Typing `gh` then asks tackd, which starts the real `gh` as you, with your terminal, environment, working folder, limits and cgroup, and the real value of `GH_TOKEN`. Signals, Ctrl-Z, the window size and the exit code pass through. A program that tackd starts is not yet protected from other processes of your user; the audit log says `unprotected (phase 4)`.
- New: `paddock tack run PROGRAM ARGS…` starts one program through tackd. Its own exit codes are 77 (tackd refuses), 69 (tackd does not answer or cannot start it) and 70 (tackd went away while it ran). Without tackd, in a sandbox and on macOS, it runs the program with the references and says so once per shell session.
- Security: tackd drops `LD_PRELOAD`, `LD_LIBRARY_PATH`, `NODE_OPTIONS`, `PYTHONPATH` and the other variables that load code from the environment of a program that it starts, and starts the program file that it hashed, not its path.
- Changed: the tackd systemd unit has no private file system view, network or system call filter any more, because the programs that it starts inherit them. It keeps its capabilities limited and `NoNewPrivileges`, and `KillMode=process`, so a restart does not stop the started programs. Run `sudo paddock tack setup` again to update it.
- Changed: `paddock tack remove` without sudo deletes your stand-ins and their PATH lines. `paddock doctor` shows which allowlisted programs reach their stand-in and what is not covered.
