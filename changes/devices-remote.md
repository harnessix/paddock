- New: `run = "remote"` forwards each request of a device to a paddock on another machine, which runs the device there in its own device sandbox, with its own table, card, audit line and log. The table names `target = "ssh://HOST"` or `"unix:/PATH"` and `device = "NAME"`, the device on the other side; no command, no shape, no sandbox table here. The local `timeout` is the whole round trip, a cancel closes the transport and the program on the other side is killed, the errors of the other side arrive unchanged (`EINVAL`, `EACCES`, `ETIME`, `ETIMEDOUT`), a transport that fails is `EIO` with the reason in `last_error` of `.catalog`, and `stream = true` brings the output as it comes.
- New: `paddock device serve-remote [--socket PATH]` serves the devices of this machine to another paddock, on the standard input and output (one request per process, as `ssh HOST paddock device serve-remote` runs it) or on a Unix socket in a 0700 folder. The identity of a remote caller is the transport: the ssh client address of `SSH_CONNECTION`, or `local` for a socket. What the caller says about itself is text for the card ("allow the device `build` for a remote caller from 192.168.1.5 (sandbox 3f2a on linuxbox)") and the audit line (`remote_caller`, `remote_host`, `remote_chain`). A remote caller gets no built-in device and no secret file. "Allow for this session" holds for 8 hours per peer and device in `~/.local/state/paddock/devices/remote-sessions.json`; `--forget` removes them.
- Security: `grant = ["remote:HOST"]` (the address, or a name that resolves to it) or `remote:any` is the only grant that reaches a remote caller; `all`, a table without a grant key, `--device`, a pasture or a project never do, and a `remote:` grant never grants to a sandbox of this host. A device without it answers `status: disabled` with the grant to add. The ssh transport runs `ssh` on the host as you, so the forward is marked like a host device: the card says "it connects to HOST with your ssh as you" and shows every session, `mode = "allow"` is a parse error for an ssh target, and the catalog text begins with "Connects to HOST with your ssh as you."
- New: `paddock device check NAME` for a remote device reaches the other side as you and prints the entry of the device there. `paddock device add NAME --run remote --target T --device D` writes the table. `paddock doctor` lists remote devices under "devices of another paddock". `paddock device ls` and `show` print `remote` and the target.
- Changed: the socket framing of the device socket carries `caller`, `caller_host` and `caller_chain` in a request header, which a per-sandbox server ignores. `ETIMEDOUT` is an error a device can answer (`DevError::TimedOut`).
