- New: `[devices.NAME]` tables take `shape` (`exec`, `serve`), `run` (`sandbox`, `host`, `remote`), `scope`, `start`, `stream`, `grant`, `mode`, `max_request`, `max_response`, `concurrency`, `idle`, `ready` and a `[devices.NAME.sandbox]` profile (`network`, `allow`, `connect`, `ro`, `rw`, `home`, `env`, `env_pass`, `credentials`, `caller`, `mem`, `cpus`). Every wrong value is a parse error that names the table, the key, the allowed values and the fix; an unknown key is an error.
- New: a sandbox sees a device when a grant covers it: `paddock run HARNESS --device NAME`, `paddock-host spawn --device NAME` from a sandbox that has it (never more than its parent), `[pastures.NAME] devices = [...]`, `grant = ["pasture:NAME", "project:PATH", "harness:NAME", "all"]` in the table, or no `grant` key at all (every sandbox, as before). A project `paddock.toml` can ask with `[devices] use = [...]` under the one-time approval; it never turns a device on. A device that no grant covers answers "disabled" and names the missing grant.
- New: `paddock device ls`, `show`, `add` and `example`. `paddock devices` stays as an alias; `budget` and `ledger` moved under `paddock device`.
- New: `paddock doctor` prints a line per device table with an old spelling (`kind = "command"`, `max_body`) and the new one, per device that runs on the host, per device without a grant whose sandbox reaches something, and per `project:` grant whose folder does not exist.
- Changed: `.catalog` is version 2. Each device has `shape`, `run`, `stream`, `grant` and `instance`. The protocol text names streaming and the exit code 7 of `paddock-host device` after a late failure. Readers of version 1 ignore the new fields.
- Changed: the audit line of a device request has `run` and `grant`; `mode = "allow"` records `allowed by grant ...` instead of a card.
- Every table of 0.2.1 parses and behaves as before. `shape = "serve"`, `stream = true`, `run = "host"`, `run = "remote"`, `scope = "shared"` and a sandbox profile beyond `network` parse and show, but their files answer `EIO` with `how_to_fix` in the catalog until a later change implements them. `isolation` (never released) is a parse error that names `run`.
